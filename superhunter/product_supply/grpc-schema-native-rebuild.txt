Run the product control
-----------------------

From a product checkout, export GRPC_SCHEMA_KIT pointing to the verified kit:

   python -B - <<'PY'
   import hashlib
   import os
   from pathlib import Path
   from superhunter.product_grpc_schema_native import run
   from superhunter.safe_io import canonical

   report = canonical(run(Path(os.environ['GRPC_SCHEMA_KIT'])))
   expected = Path('superhunter/product_supply/grpc-schema-native-result.json').read_bytes()
   assert report == expected
   print(hashlib.sha256(report).hexdigest())
   PY

Each invocation uses a new temporary directory. The accepted report contains
5,148 canonical bytes with SHA256
6d4d608996df72997bfc31554fcf831505a2630e9ffb169e387bf51ea7e27261.
Two actual runs produced those same bytes on the same host with the same kit.
They are execution replays, not independently authenticated hosts or builds.

The API accepts only a kit directory. Sources, symbols, commands and expected
changes are fixed and pinned. All commands use -use-reflection=false and only
list/describe with local -proto or -protoset files. No server address, RPC
invocation, credential, listener or external target is supplied. Every process
runs under unshare --user --map-current-user --net, has closed stdin, a ten-second
timeout and bounded accepted output. User/network namespaces restrict
networking; they do not constitute a complete filesystem/syscall sandbox.

What the witness establishes
---------------------------

For each of two OWNED proto3 schemas, the product checks the service list,
method list, service description and two message descriptions. grpcurl exports
a FileDescriptorSet; an independently implemented, bounded Python wire decoder
extracts messages, field numbers/types and method streaming signatures. Those
values must match the separately authored OWNED schema model. Independently
rendered text from the decoded model must match all five grpcurl views.

The product then asks the same grpcurl build to read the exported protoset and
repeat those five views. This is ten source views and ten protoset views per
run. The protoset replay is not a second protobuf implementation; the separate
bounded descriptor decoder supplies the independent structural witness.

The changed schema removes Ledger.Balance, adds Ledger.GetBalance, changes
Ledger.Watch from server-streaming to unary, and changes balance_minor from
uint64 (wire type 0) to string (wire type 2). These observations do not infer
that the two method names represent a semantic rename.

Two malformed derivatives are rejected by grpcurl: duplicate field number and
unknown response message. A nonexistent symbol is also rejected in each valid
schema. Rejection requires the expected nonzero exit, empty stdout and exact
diagnostic digest; a timeout, network error or generic failure cannot count as
the expected rejection. The sample JSON contains actual captured producer
outputs used by the verifier regressions.

   python -B -m unittest superhunter.tests.test_product_grpc_schema_native -v

Ten focused tests cover substituted source/descriptor bytes, forged text,
missing protoset views, resealed type substitutions, ambiguous/truncated wire
data, false native failures and altered pins. They test the verifier; the two
recorded native runs separately demonstrate producer execution.

Scope and notices
-----------------

This is two fixed schemas and two malformed derivatives. The descriptor reader
accepts only the bounded subset used by these controls; it is not general
protobuf validation or a general compatibility analyzer. Schema differences do
not establish authorization behavior, live API exposure or vulnerabilities.
Confirmed original vulnerabilities: zero.

The original grpcurl MIT license is retained unchanged. Its transitive module
and Go runtime distribution obligations are not certified by this functional
integration, and no commercial clearance is implied.
