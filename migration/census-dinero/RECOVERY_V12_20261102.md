## Problemas reproducidos y correcciones

Los `meta.json` de `corridas/40215984099/` documentan estos fallos:

| Cadena | Evidencia retenida | Consecuencia |
| --- | --- | --- |
| Flare | Máximo 30 bloques; sonda empezó por 1,000 | Falso descarte de getLogs |
| Monad | HTTP 413 / rango excesivo en la primera prueba | Capacidad no establecida |
| HyperEVM | Rate limit en un proveedor; falla posterior de rango en otro | No se conservó el prefijo leído |
| Soneium | HTTP 429 durante la recolección | No se conservó el prefijo leído |
| Cronos | Historia podada en un proveedor, HTTP 429 en otro | Cobertura incompleta |
| Sei | Bloques antiguos podados | Archivo histórico pendiente |
| Corn | Proveedor no pudo procesar la solicitud | Disponibilidad pendiente |
| Gensyn | HTTP 400 en la sonda | Capacidad no establecida |

La sonda ahora empieza por un bloque y aumenta después de cada respuesta
válida, incluyendo rangos de 10 y 30 bloques. Distingue `supported`,
`unavailable` y `unverified`; un HTTP 400/429 o datos podados no prueban que
el método no exista. Una falla transitoria inicial se reintenta una sola vez
con el mismo rango, después de una pausa. No se cambian permisos ni proveedores.

Una interrupción definitiva de getLogs conserva logs del prefijo y el primer
bloque no leído. El Collector registra `log_interruptions`, deja la consulta
de eventos incompleta como fallo y no atribuye cobertura al bloque fallido.
Se mantiene la intersección de cobertura entre protocolos. Los consumidores
que requieren resultados completos siguen recibiendo una subclase de RpcError.
