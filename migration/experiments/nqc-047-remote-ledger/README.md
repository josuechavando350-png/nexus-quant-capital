# NQC047 — bitácora remota GitHub con transporte sintético

19 de octubre de 2026. Base única: NQC046 \`1da9ab0c6651d5922d5600e53dabcf5963dcb13a\`. Rama de investigación: \`research/nqc-047-remote-ledger-20261019\`. No se modifica \`main\`, NQC040, NQC038, workflows ni ninguna aplicación.

## Resultado nuevo reproducible

\`ledger_engine.js\` aporta un motor de registro remoto **DRY_RUN** con 8 operaciones en el orden fijado. \`github_connector_adapter.js\` fija repositorio, rama y la ruta **única** \`evidence/DRYRUN_JOURNAL.json\`; usa el GitHub conectado con \`fetch_commit\`, \`fetch_file\` y \`update_file\`. No crea sesiones ni nuevos presupuestos al reanudar y no fuerza refs. El modo LIVE está **deshabilitado**.

Antes del transporte simulado se escribe una fila \`RESERVED\` mediante actualización condicional del SHA del blob previo; se exige recuperar exactamente el commit de respuesta y observarlo como cabeza de rama. Después de recibir la respuesta sintética se escribe \`RECEIVED\` junto con el contenido y su SHA-256. Solo tras recuperarlo, verificar su integridad y pasar el validador inyectado se escribe \`VERIFIED\` y se habilita otra reserva. Las respuestas previas se revalidan desde el inicio en cada ejecución. \`RESERVED\` sin respuesta, \`REJECTED\`, falla de validador, respuesta insegura o confirmación de persistencia ambigua detienen el proceso. Una falla después de persistir \`RECEIVED\` admite recuperación y revalidación **offline**, sin retransmitir. El resultado de una confirmación ambigua no se presume fallido ni exitoso.

Con **GitHub real**, dos solicitudes sintéticas se registraron y verificaron en ejecuciones nuevas; se observó la revalidación de la primera antes de simular la segunda. En el tercer intento se aceptó la reserva remota y el harness descartó intencionalmente la confirmación. El motor devolvió \`BLOCKED_AMBIGUOUS_WRITE\` sin llamar siquiera al transporte simulado; al reanudar, \`BLOCKED_AMBIGUOUS_ATTEMPT\`, con cero envíos. No se borró ni reinició esa bitácora. En archivo DRY_RUN independiente, GitHub devolvió 409 para una actualización secuencial con SHA obsoleto y conservó la versión ya escrita. **Eso NO prueba una carrera concurrente real ni exclusión global entre hosts.**

La suite \`test_ledger.js\` (15 pruebas, 15 aprobadas en el evaluador JS con los bytes recuperados desde GitHub) cubre orden, recuperación, fallas antes/después de commits, respuesta recuperada, límites, validación, protección ante eco de clave sintética y ausencia de novena lectura. Este número es adicional como suite nueva de NQC047; **no se suma repetidamente a las 140 pruebas históricas previas**. Los commits y el límite probatorio constan en \`evidence/GITHUB_DRYRUN_PROBE.json\` y \`VALIDATION.json\`. Para un ejecutor con checkout y Node, la reproducción offline es \`node migration/experiments/nqc-047-remote-ledger/test_ledger.js\`; el dueño del teléfono Android no necesita ejecutar esa instrucción.

## Límite técnico de la integración

La recuperación y el bloqueo del contador sintético están observados mediante GitHub conectado. **No es todavía un adaptador LIVE apto para enviar lecturas Triport**. El callback usado en DRY_RUN solo acepta cadenas \`SIM_ACCEPTED_n\`; no es el validador Merkle de NQC037 ni ejecuta NQC040/NQC038 Python. El contenedor local de esta conversación carece de acceso DNS directo a GitHub y de la dependencia \`rlp\`; no se ejecutaron en él las suites Python ni el verificador global de aislamiento. El conector GitHub permite transiciones remotas desde su runtime JS, pero no ofrece directamente un puente documentado y seguro hacia el ejecutor Python con clave de Triport. Las variables \`NQC_TRIPORT_API_KEY\` y \`NQC_ARCHIVE_RPC\` estaban ausentes en ese contenedor (solo comprobación booleana).

El archivo de respuesta se mantiene **dentro del propio commit del journal**, protegido por SHA-256 interno y blob Git, con máximo de **650 000 bytes UTF-8 para todo el journal**. Esta limitación es deliberada para no suponer soporte del conector para respuestas grandes; NO cubre el límite NQC038 de 16 MiB. Una respuesta demasiado grande consume la reserva y detiene esta vía sin solicitarla otra vez. GitHub Contents usa el SHA del contenido en escrituras, pero no se ha ensayado una carrera simultánea ni se ha excluido un rollback externo de la rama por otro actor. El contador no es un servicio distribuido autoritativo bajo actores deshonestos o copias restauradas. La rama y el archivo DRY_RUN no equivalen a un registro LIVE ni autorizan crear uno nuevo.

Para habilitar una lectura real hacen falta, **conjuntamente**, un canal soportado de credencial protegida, garantía operacional del único registro y su política antirrollback, integración efectiva del verificador NQC037/NQC038 con las respuestas persistidas (incluidas grandes), y prueba adversarial multi-host. No se debe improvisar traslado de clave ni usar el teléfono como sustituto de un ejecutor. El permiso sigue limitado a **ocho lecturas Triport TOTAL** conforme al plan fijo anterior, sin reintentos ni proxies alternos, y actualmente **ninguna se ha enviado**.

No existe evidencia histórica de preestado exacto, canonicidad/finalidad independiente ni replay Nitro. \`commercial_admission=false\`; ninguna prueba sintética acredita rentabilidad.
