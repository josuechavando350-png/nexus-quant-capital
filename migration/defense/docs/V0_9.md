# 0.9.0: presupuesto persistente para escritores del archivo

`archive_budget` conecta la capacidad de almacenamiento con cada publicación de páginas, manifiestos y catálogos. `ArchiveStore.configure_budget` instala una política canónica privada con máximos de bytes lógicos y objetos. Devuelve su SHA-256, que se retiene fuera del archivo para reabrir `ArchiveStore` con `budget_digest`. La política se crea sin reemplazo; solo se recupera una instalación previa cuando sus bytes son idénticos. No existe una operación que eleve automáticamente límites ni sobrescriba la política.

La configuración verifica el uso actual, incluida la propia política. Un presupuesto insuficiente se rechaza antes de instalarla. Cuentan todos los archivos regulares observados en raíz/pages/manifests: objetos referenciados, objetos fuera de selección, temporales y desconocidos. El inventario identifica `archive-budget.json` como `control`; su contenido se autentica mediante el digest del presupuesto, no mediante la selección de catálogos de auditoría. Los máximos configurables siguen los del escáner: 4 GiB lógicos y 20.000 objetos.

Todos los escritores de esta versión adquieren un bloqueo `flock` del inode del directorio antes de publicar, también cuando todavía no existe política. Se comprueba la identidad del directorio abierto. La espera es de hasta cinco segundos con rechazo explícito `archive_writer_busy`; cerrar el descriptor o terminar el proceso libera el bloqueo. La configuración toma ese mismo bloqueo, por lo que un escritor abierto antes de instalar la política la detecta en su siguiente publicación y exige pin. Lecturas de evidencias siguen siendo compatibles sin ese pin.

Dentro del bloqueo se relee la política y se compara con el hash externo. Si falta, fue alterada o no coincide, el escritor fijado rechaza. Si existe pero no se suministró pin, se rechaza la escritura. Después se enumera el uso real con el escáner limitado del inventario. No hay un contador de consumo en memoria o una reserva SQLite que pueda olvidarse tras reiniciar. Para un objeto nuevo se comprueba el incremento de bytes y un objeto antes de escribir. Se releen política y uso después de publicar, antes de confirmar.

Un objeto ya existente solo se reutiliza tras comparar sus bytes y sincronizar archivo/directorio. Esta ruta no crea otra copia temporal, por lo que un reintento idéntico puede completarse a capacidad exacta. Un objeto alterado no se sobrescribe. La deduplicación está dentro del bloqueo: seis procesos que intentan el mismo contenido terminan con un solo objeto; si compiten con contenidos distintos por el último espacio, solo uno publica. Se comprobó también contención entre hilos con instancias independientes.

Los objetos nuevos conservan la publicación de 0.6.0: temporal exclusivo, escritura/sincronización, enlace final sin reemplazo y retirada de su propio temporal. El temporal y el nombre final comparten brevemente el mismo inode; no hay una segunda copia de datos, pero sí dos nombres durante ese tramo. Un cese antes del enlace deja un temporal contabilizado por la próxima consulta. Un cese después del enlace puede dejar dos nombres enlazados; el escáner los rechaza y exige revisión. Ninguno de estos casos activa limpieza automática. No se promete un máximo estricto de nombres transitorios ni de bloques físicos.

El presupuesto se aplica por publicación, no como una transacción de todo el intervalo. Si se agota después de algunas páginas, estas permanecen para revisión/reintento y consumen espacio. No se publica el manifiesto completo ni se avanza el testigo sin verificar todo el intervalo. Los catálogos de cobertura usan el mismo camino presupuestado. Un fallo posterior de sincronización puede dejar un objeto final válido; el reintento lo compara, sincroniza y recupera sin consumir otro espacio. La instalación de política también permite recuperar una confirmación perdida por fallo de sincronización del directorio.

La herramienta `archive_audit.py` añade `configure-budget`, `budget-status`, límites opcionales emparejados para `init` y el argumento global `--budget-digest`. El comando del motor `archive-audit` añade `--archive-budget-digest`. `budget-status` devuelve uso, capacidad restante y `within_budget`; la CLI termina con código 2 si se ha excedido el presupuesto. Los errores de integridad, bloqueo o límites también rechazan. La API no cambia firmas de los métodos de lectura existentes; el constructor de `ArchiveStore` añade el pin opcional.

Validación: 30 pruebas nuevas, 285 del paquete y 9 de aislamiento. Incluyen límites exactos de bytes/objetos, política perdida/alterada, permisos/enlaces, configuración repetida, archivos previos, temporales, crecimiento externo, hilos y procesos competidores, espera acotada del bloqueo, fallos de sincronización, procesos que terminan abruptamente antes/después del enlace, agotamiento a mitad de intervalo y al publicar manifiesto/catálogo. Se ejecutan ambas CLI con y sin el pin, incluyendo `archive-audit` del motor. Las pruebas de almacenamiento usan bytes explícitos de prueba; las aceptaciones de integración usan fuentes reales y SQLite/archivos reales.

La aceptación específica archiva una admisión de una copia de `engine.py` hasta ocupar seis objetos: política, tres páginas, manifiesto y catálogo. Recupera el mismo intervalo y catálogo a capacidad completa. Una segunda admisión eleva el motor al registro 6, pero el archivo rechaza crecer: el testigo sigue en el registro 3 y los bytes archivados no cambian. El consumidor del manifiesto real de NQC reabre un presupuesto de 1 MiB/64 objetos y verifica diez objetos concordantes entre inventario y estado del presupuesto. Las fuentes originales permanecen intactas.

Alcance: control local para procesos que utilizan esta versión y respetan el bloqueo. No es cuota del sistema operativo, reserva de disco, lock distribuido ni resistencia a un administrador; otro proceso o una versión anterior puede escribir directamente. El estado reporta crecimiento externo observado y rechaza nuevas publicaciones, sin borrar archivos. SQLite del motor/testigo y exportaciones fuera del almacén no están bajo este presupuesto. No se han probado sistemas de archivos de red, cortes eléctricos físicos ni hardware de almacenamiento. Las enumeraciones añaden coste lineal por objeto publicado. Los formatos anteriores conservan compatibilidad; configurar el presupuesto es explícito. No se despliega ni activa producción y no se incrementa el número de módulos originales implementados.
