# 0.3.0: consumo de los bytes inspeccionados

Antes, `Engine.process` devolvía una decisión sobre un archivo. Un consumidor que después abriese su ruta podía leer bytes distintos. La API anterior sigue disponible para inspección; la API nueva `Engine.admit_bytes` conserva la captura exacta y la devuelve únicamente si la decisión es `admit` y la transacción SQLite completa se confirma.

`ArtifactReader.read_json` consume esa captura con el parser acotado existente. El comando local `read-json` recibe por stdin el mismo sobre `{token, request}` de `inspect`, con las rutas de control y política suministradas por el operador. El resultado contiene admisión, hash SHA-256, tamaño y datos analizados. No cambia la superficie HTTP.

La auditoría agrega `snapshot_authorized` dentro de la transacción de la decisión. El verificador exige que siga inmediatamente a una admisión con recibo válido y coincida en tiempo, sujeto, solicitud, activo, hash del recibo, política y hash observado. El tamaño queda autenticado como dato del productor; no se vuelve a medir en la exportación porque esta no incluye el contenido. La clave de auditoría conserva su significado durante todos los registros, corregido al probar una autorización seguida de otra decisión.

Se añadieron 19 pruebas. Incluyen sustitución real del archivo después de capturarlo, rechazo por cambios de artefacto/señuelo, symlink, token de uso único, cuota, expiración de evidencia, límite y errores de JSON, CLI, 16 solicitudes concurrentes y adulteración del vínculo de auditoría. Dos fallos reales de SQLite inducidos en una base temporal prueban rollback: rechazo de inserción de auditoría y violación diferida de clave foránea al confirmar. Ninguno entrega bytes ni consume definitivamente el token.

El control de integración lee el manifiesto real `migration/source-manifest.json`, con 337.100 bytes y 637 entradas, a través de ese lector. Comprueba hash, recibo, exportación autenticada y aislamiento después de retirar únicamente el señuelo nuevo propio. La suite completa suma 123 pruebas del paquete y 9 de aislamiento.

La autorización del snapshot no demuestra que el parser terminó ni que una aplicación posterior recibió o procesó los datos. El parser puede fallar después de consumir el token. Un proceso puede terminar después del commit sin entregar el resultado. No hay garantía de entrega exactamente una vez. No se activó el consumidor productivo de Census ni se modificaron sus fuentes originales.
