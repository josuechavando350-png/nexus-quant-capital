# 0.13.0 — evidencia preservada de casos de autenticación

La entrega permanece en `NQC-defensive`, sin cambios en SuperHunter ni activación productiva. Añade captura y verificación offline sobre los casos ya producidos por la ingesta JSONL/OpenSSH/journald.

## Lo que conserva

`capture_case` obtiene una instantánea SQLite del caso, su configuración y los eventos que activaron la regla. Exige identidad de cliente/activo/caso, digest externo del caso y el pin de configuración retenido al registrar la fuente. Después lee solamente archivos elegidos explícitamente dentro de esa fuente y conserva los rangos de bytes referenciados.

Comprueba identidad de archivo (dispositivo/inode), generación, rango, hash de línea, normalización del mensaje, pertenencia al caso y condiciones del umbral/ventana. El paquete JSON canónico contiene el caso, configuración, eventos, metadatos de los archivos y bytes de cada registro codificados en base64. No incluye las demás líneas del log. Base64 no cifra el contenido: el paquete contiene datos originales y rutas de configuración.

Una alteración durante la lectura o de los bytes referenciados impide publicar la adquisición. Se admiten casos repartidos entre archivos rotados, siempre que se indiquen todas sus generaciones. Una copia del archivo con otro inode no sustituye automáticamente al original. Los archivos fuente no se modifican.

El resultado se escribe mediante publicación sin reemplazo y `fsync`; se relee y verifica antes de confirmar. El directorio de destino debe existir y ser privado (0700); el archivo se crea con permisos 0600. Si una escritura o relectura falla, no se devuelve éxito. Puede quedar un archivo publicado o temporal para revisión si el fallo ocurre después de escribir; no se realiza borrado automático ni recuperación automática de confirmaciones perdidas.

## Uso

Desde `migration/defense`, consultar un caso abierto de autenticación:

```bash
python3 -B tools/case_evidence.py describe --store-root /ruta/operaciones --tenant propio --asset servidor --case-id ID
```

Devuelve `case_digest`, `config_digest`, número de registros y generaciones necesarias. Comparar `config_digest` con el pin conservado al registrar la fuente; una descripción obtenida de la propia base no sustituye ese valor externo. Conservar también el digest de la instantánea del caso.

Crear un archivo de selección con las rutas relativas reales, por ejemplo:

```json
[{"generation":0,"name":"auth.old"},{"generation":1,"name":"auth.log"}]
```

No acepta rutas absolutas, `..`, generaciones repetidas ni archivos adicionales fuera de las generaciones requeridas. Para un caso de una sola generación, proporcionar solo esa entrada.

```bash
python3 -B tools/case_evidence.py capture --store-root /ruta/operaciones --tenant propio --asset servidor --case-id ID --case-digest CASE_DIGEST --config-digest CONFIG_DIGEST --source-map /ruta/seleccion.json --output /ruta/privada/evidencia.json
```

Los identificadores/digests del ejemplo son parámetros del operador. La respuesta devuelve `bundle_digest` y confirma la relectura. Retener ese digest y los demás valores esperados fuera del paquete. La verificación posterior no requiere la base ni los logs originales:

```bash
python3 -B tools/case_evidence.py verify --input /ruta/privada/evidencia.json --digest BUNDLE_DIGEST --tenant propio --asset servidor --case-id ID --case-digest CASE_DIGEST --config-digest CONFIG_DIGEST
```

El verificador nunca abre rutas contenidas en el paquete. Comprueba el hash externo y la estructura, vuelve a interpretar los bytes mediante los parsers existentes, exige referencias completas/ordenadas y verifica principal, dirección, número de fallos, ventana e identidad calculada del caso. También rechaza registros nativos repetidos entre las pruebas del disparo.

## Alcance de la comprobación

- Preserva exactamente los registros que dispararon un caso de `auth_failure_burst_v1`; hasta 100 registros y 8 generaciones, 16 KiB por registro, 16 MiB por archivo fuente, 64 MiB de fuentes aceptadas, 2 MiB de bytes preservados y 8 MiB por paquete.
- Las lecturas son individuales y verificadas, no un snapshot atómico entre todos los archivos. Los límites de bytes son de entrada/salida lógica, no promesas sobre memoria máxima del proceso o cuota física de disco.
- El paquete incluye la instantánea fijada del caso; no certifica que sea el estado más reciente al consultarlo después.
- La comprobación de disparo cubre los eventos incluidos. No contiene todo el historial del episodio y no demuestra ausencia de éxitos u otros eventos intermedios. No equivale a reproducción completa de la ingesta.
- Los hashes y pins externos permiten comprobar igualdad e integridad respecto a esos valores. No autentican por sí mismos al productor del log, al operador o al autor de una acción. Quien controla conjuntamente datos y todos los pins puede sustituirlos.
- El almacén operativo sigue sin anclaje independiente; no se afirma cadena de custodia legal, firma de adquisición, admisibilidad judicial ni certificación forense.
- El verificador offline comparte parsers con la ingesta; no es una implementación independiente.
- Los casos de integridad mantienen su archivo/ledger existente. Esta herramienta rechaza esos casos en vez de presentar un paquete vacío como adquisición de sus bytes.

## Validación

```bash
python3 -B tools/check_case_evidence.py
python3 -B -m unittest discover -s tests -p test_case_evidence.py -v
```

La aceptación crea registros de formato OpenSSH explícitamente sintéticos en archivos reales, produce un caso a través de dos generaciones y conserva tres líneas. Verifica que la adquisición no cambie las fuentes, rechaza otra adquisición tras modificar un registro y verifica el paquete después de retirar logs y base temporales. También rechaza un paquete modificado.

Las 40 pruebas nuevas cubren JSONL y journald, límites, ámbito, pins, cambios durante lectura, archivos cambiados o faltantes, enlaces, pérdida de referencias, corrupción, fallos de escritura/relectura, selección de rotación y CLI offline. No se ejecutan servicios ni pruebas sobre activos ajenos.
