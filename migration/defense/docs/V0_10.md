# 0.10.0 — protección local de extremo a extremo

`ManagedIntegrity` conecta el motor, lector, ledger, testigo y archivo existentes. Inicializa un directorio nuevo con una copia de un JSON del operador, un canary y dos copias de recuperación fijadas por hashes. El archivo fuente no se altera. Las pruebas usan archivos y SQLite reales; las alteraciones de ensayo son explícitas y quedan dentro de directorios temporales.

## Operación

Desde `migration/defense`, Linux y Python 3.11+:

```bash
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed init /ruta/existente/config.json
```

El padre de `managed` debe existir; `managed` no debe existir. Conservar el `manifest_digest` devuelto fuera del directorio administrado. Las siguientes órdenes exigen ese valor como argumento de `--manifest-digest`:

```bash
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed --manifest-digest DIGEST inspect
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed --manifest-digest DIGEST read-json
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed --manifest-digest DIGEST status
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed --manifest-digest DIGEST recover
python3 -B tools/managed_integrity.py --root /ruta/nueva/managed --manifest-digest DIGEST archive
```

`DIGEST` es el valor real devuelto por `init`, no un secreto ni un valor fijo incluido en el programa. `monitor --samples 10 --interval-seconds 3` realiza diez observaciones; no instala tareas ni demonios. `read-json` entrega contenido: tratar su salida conforme a la sensibilidad del archivo.

Una modificación detectada abre el caso y pone en cuarentena al activo dentro del lector. Una inspección de un activo ya contenido devuelve el caso existente y `observation_performed: false`; no afirma haber obtenido otra observación. La recuperación es una orden explícita del operador, nunca una reacción automática del monitor.

La recuperación comprueba ambas copias antes de escribir, rechaza enlaces, reemplaza exclusivamente `assets/artifact.json` y `assets/canary`, sincroniza archivos/directorio, exige que el motor compruebe su estado y registra la liberación. Después realiza una lectura admitida real. Un fallo de escritura o de auditoría de liberación conserva la cuarentena. Un fallo posterior a la liberación puede impedir la lectura final: en ese caso no se devuelve éxito de recuperación; la liberación confirmada permanece registrada. No se promete entrega exactamente una vez.

El caso mostrado es el último del activo, derivado de eventos autenticados. El historial sigue en el ledger. `archive` conserva y verifica los registros, hashes y recibos, no una imagen forense completa de todos los bytes alterados. No archiva automáticamente cada inspección.

## Comprobación reproducible

```bash
python3 -B tools/check_managed_integrity.py ../..
python3 -B tools/check_operational_catalog.py
python3 -B -m unittest discover -s tests -v
```

La primera orden recorre observación, cambio controlado de una copia del manifiesto NQC, incidente, rechazo del consumidor, archivo, reapertura, recuperación, lectura y segundo archivo. Comprueba que la fuente original siga idéntica y que el testigo coincida con el motor. La segunda verifica IDs, referencias, ausencia de ciclos y rutas de implementación declaradas; no certifica funcionamiento de los componentes pendientes.

## Límites

- Protección de un JSON administrado y su canary; no aislamiento de máquina, proceso, red o identidad.
- Observación por solicitud o muestreo; un cambio transitorio entre muestras puede no verse.
- El consumidor debe usar este lector. Otros procesos con acceso directo al archivo no quedan bloqueados.
- Permisos locales y `flock` coordinan procesos cooperantes; no se afirma resistencia contra un administrador o el mismo usuario hostil.
- Referencia de recuperación elegida al inicializar: verifica igualdad, no que la configuración original sea segura.
- El testigo y las claves siguen locales. No existe custodia externa ni réplica independiente.
- El historial se verifica completo; todavía no hay retención ni rendimiento productivo medido.
- No hay activación del circuito productivo de Census ni cambio de sus fuentes.

La arquitectura C001–C100 y las especialidades D001–D100 son requisitos enlazados. C014, C032, C041, C052, C064, C067, C082, C095 y C096 tienen implementaciones de alcance parcial; los otros 91 componentes permanecen pendientes. No hay clases vacías para representar funciones futuras.
